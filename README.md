# Data Quality Pipeline Lab

**CSV를 검증하고, 오류 행을 분리하며, 재실행과 충돌 상황에서도 저장 결과를 지키는 실습입니다.**

합성 주문 데이터로 누락값·중복 ID·잘못된 날짜를 탐지합니다.
데이터 품질 기준을 통과한 행만 SQLite에 저장하고, 동일 입력을 다시 처리해도 행이 늘어나지 않는지 확인합니다.

## 바로 실행

Python 3.11 이상, 추가 패키지·API 키·서버 없이 실행합니다.

```bash
python -m unittest -v
python run_demo.py --output runs/local-01
```

항상 새로운 결과 폴더를 지정하세요. 기존 실험 기록은 덮어쓰지 않습니다.
[실행 결과 표](example-summary.md) · [실제 결과 JSON](example-summary.json)

## 전체 실험에서 확인하는 것

| 단계 | 결과 | 유효 후보 | 격리 | 신규 저장 | 재실행 건너뜀 |
|---|---|---:|---:|---:|---:|
| 오류 CSV | 차단 | 6 | 4 | 0 | 0 |
| 수정 CSV | 저장 | 10 | 0 | 10 | 0 |
| 같은 CSV 재실행 | 저장 완료 | 10 | 0 | 0 | 10 |
| 기존 ID의 다른 내용 | 충돌로 전체 취소 | 2 | 0 | 0 | 0 |
| 올바른 CSV로 복구 실행 | 저장 완료 | 10 | 0 | 0 | 10 |

오류 CSV에는 불가능한 날짜 1건, 누락 수량 1건, 중복 ID 2건이 있습니다.
중복 ID는 어느 행을 우선할지 임의로 결정하지 않고 **해당 ID의 모든 행을 격리**합니다.
충돌 실험은 새로운 행을 먼저 삽입한 뒤 기존 ID와의 충돌을 발생시켜, 앞선 삽입까지 롤백되는지 확인합니다.
마지막에는 저장된 전체 행 내용이 이전 스냅샷과 같고 행 수가 10개인지 검사합니다.

## 품질 기준

- 헤더는 `order_id,order_date,quantity,unit_price` 순서와 정확히 일치해야 합니다.
- 날짜는 유효한 ISO 날짜, 수량은 1~10,000 범위의 ASCII 정수입니다.
- 단가는 0~1,000,000 범위이고 소수점 아래 둘째 자리까지 정확히 표현 가능해야 합니다.
- 금액은 Decimal로 검증하고 정수 센트로 저장합니다. 실제 통화·결제 데이터는 아닙니다.
- 앞뒤 공백은 정리하며, UTF-8 BOM을 허용합니다.
- 오류율은 **격리 레코드 수 / 파싱된 전체 데이터 레코드 수**입니다.
- 오류율이 20%를 초과하면 저장을 차단합니다. 정확히 20%이면 유효 행만 저장합니다.
- 헤더·인코딩·CSV 구문 오류나 빈 데이터는 오류율과 관계없이 차단합니다.

빈 줄은 Python CSV 파서가 건너뜁니다. 레코드 번호는 물리적인 파일 줄 번호와 다를 수 있습니다.
구문·인코딩 오류가 있으면 일부 레코드만 파싱됐을 수 있으므로 그 실행의 오류율을 전체 파일 품질로 해석하면 안 됩니다.

## 개별 파일 처리

```bash
python pipeline.py sample-corrected.csv --db runs/warehouse.sqlite --output runs/import-01
python pipeline.py sample-corrected.csv --db runs/warehouse.sqlite --output runs/import-02
```

종료 코드 0은 저장 완료, 2는 품질 또는 목적지 충돌로 인한 차단입니다.
파일 접근·DB 장애 등 예상하지 못한 시스템 오류는 예외로 종료합니다.

각 실행은 다음을 남깁니다.

- `valid.csv`: 정규화한 유효 **후보**. 이 파일이 존재한다고 DB 저장이 성공한 것은 아닙니다.
- `quarantine.jsonl`: 오류 사유·레코드 번호·원본 행
- `report.json`, `report.md`: 상태, 오류율, 저장·건너뜀 건수, 소스와 코드 SHA-256

## 중복과 충돌은 다르게 처리

**파일 내부 중복:** 같은 ID가 반복되면 해당 ID 전체 격리.

**이미 저장된 데이터와 동일:** ID·날짜·수량·금액이 같으면 건너뜀.

**이미 저장된 ID와 다른 내용:** 자동 덮어쓰지 않고 그 실행의 DB 변경 전체 롤백.
기존 데이터의 정정·삭제는 별도 업무 흐름이 필요하며 이번 실습에 포함하지 않았습니다.

## 검증

Windows / Python 3.11에서 14개 테스트와 5단계 실험을 실행했습니다.
GitHub Actions는 Python 3.11·3.12에서 같은 검증을 수행하고 합성 데이터 실험 기록을 artifact로 보관합니다.
주요 테스트는 20% 경계값, 모든 중복 행 격리, NaN/무한대/소수 정밀도, 잘못된 CSV, 재실행과 트랜잭션 롤백입니다.

## 범위와 한계

- 실제 고객 데이터 없이 직접 생성한 작은 합성 데이터만 사용합니다.
- CSV를 메모리에 모아 검사합니다. 대용량 스트리밍 파이프라인이나 분산 처리 성능을 증명하지 않습니다.
- 입력 파일은 검사 중 변경되지 않는다는 전제입니다. SHA-256은 재현용 식별자이며 파일 잠금이나 서명이 아닙니다.
- SQLite 트랜잭션은 DB 변경을 원자적으로 처리합니다. 진단 파일과 DB를 묶는 분산 트랜잭션은 아닙니다.
- DB 커밋 뒤 보고서 저장이 실패할 수 있습니다. 이때 새 결과 폴더로 재실행하면 동일 행은 건너뜁니다. 디스크 고갈·강제 종료 실험은 포함하지 않았습니다.
- 격리 파일에는 원본 값이 남습니다. 실데이터 적용 시 마스킹·접근 제어·보관 기간을 별도로 설계해야 합니다.
- 보고서·DB의 버전 관리, 스키마 마이그레이션, 스케줄링, 알림·대시보드는 포함하지 않았습니다.
